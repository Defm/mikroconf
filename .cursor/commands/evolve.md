# /evolve — развитие правил поведения

Преобразуй устойчивые исправления поведения агента в явные правила
`LLM-RULES.md` в корне проекта.

Эта команда — единственный допустимый способ создавать и изменять
`LLM-RULES.md`. Во время обычной работы не редактируй этот файл напрямую:
сначала собери наблюдения, затем предложи правила и получи отдельное одобрение
пользователя для каждой записи.

Приоритет при конфликте:
`USER-RULES.md` → `LLM-RULES.md` → `AGENTS.md` и `.cursor/rules/`.

Без аргумента выполни полный проход. Аргумент `show` формирует отчёт без
изменений.

## Полный проход

### 1. Собери наблюдения

Используй:

1. исправления и уточнения пользователя в текущем диалоге;
2. прямые просьбы закрепить постоянное поведение;
3. существующие записи `LLM-RULES.md` и их `Evidence`;
4. переданный пользователем текст.

Не используй повторно эпизод, уже отражённый в `Evidence`.

### 2. Сгруппируй наблюдения

Одна модель поведения образует не более одного предложения правила.
Предлагай правило после двух независимых эпизодов. Одного эпизода достаточно,
если пользователь прямо потребовал постоянного изменения поведения.

Не предлагай правило, противоречащее `USER-RULES.md`. Сначала покажи конфликт
и запроси решение пользователя.

### 3. Защити критические области

Отдельно отмечай предложения, ослабляющие:

- защиту секретов и внешних данных;
- подтверждение внешних записей, публикаций и `push`;
- проверку результата;
- SDD-gates;
- загрузку `USER-RULES.md` и ритуал ответов.

Для ослабления такого правила требуется отдельное явное подтверждение.
Предпочитай сужение области действия полному удалению gate.

### 4. Получи одобрение

Покажи нумерованные предложения. Для каждого укажи:

- точный текст правила;
- область действия;
- наблюдения;
- уточняемый раздел `USER-RULES.md`, `AGENTS.md` или `.cursor/rules/`;
- влияние на критические gates.

Без отдельного одобрения не записывай и не изменяй правило.

### 5. Обнови LLM-RULES.md

Если файла нет, создай структуру:

```markdown
# LLM Rules

Last /evolve run: YYYY-MM-DD

## Active rules

## Superseded
```

Записи пиши по-английски, императивно:

```markdown
### R-001 — <short title> (YYYY-MM-DD)

- **Rule:** <imperative behavior rule>
- **Scope:** <when it applies>
- **Evidence:** <approved episodes>
- **Refines:** <canonical section>
```

Нумеруй записи последовательно. Объединяй дубликаты. При замене перемещай
прежнюю запись в `## Superseded` и указывай новую запись и дату. Не оставляй
два противоречащих активных правила.

Если активных записей стало больше двадцати, сначала предложи консолидацию.

### 6. Заверши проход

По-русски перечисли созданные, объединённые, заменённые и отклонённые записи,
а также наблюдения, которым пока не хватает подтверждений.

## show

Покажи идентификаторы и названия активных правил, дату последнего прохода
и накопленные в текущем диалоге наблюдения. Ничего не изменяй.

## Ограничения

- Команда изменяет только `LLM-RULES.md`.
- Каждое изменение требует одобрения пользователя в текущем проходе.
- Команда не запускается без запроса пользователя.
- `USER-RULES.md`, `AGENTS.md`, `.cursor/rules/`, шаблоны и `.dev.env`
  команда не изменяет.
