# /sdd-archive — архивация

Ожидаемый режим: **Agent mode**. Первой строкой ответа назови режим.

Аргумент: `<NNN-name>`; если не передан, выбери через `AskQuestion` среди
изменений со статусом `verified`.

## Порядок

1. Если статус не `verified` — предупреди и продолжай только после явного
   согласия пользователя.
2. Если для изменения создавался Cursor-план, проверь, что
   `spec/changes/<NNN-name>/plan.md` совпадает с актуальным планом, включая
   статусы todos; при расхождении обнови копию.
3. Для каждой дельты `specs/<capability>/spec.md`:
   - `ADDED` — добавь требования в `spec/capabilities/<capability>/spec.md`,
     создав файл по шаблону `spec/templates/spec.md`, если его нет;
   - `MODIFIED` — замени требование с тем же названием целиком;
   - `REMOVED` — удали требование с этим названием.

   Покажи итоговый diff capabilities.
4. Выполни задачи этапа архивации из `tasks.md` изменения, если они есть,
   и отметь их.
5. Поставь `Статус: archived` и перемести папку в
   `spec/changes/archive/ГГГГ-ММ-ДД-<NNN-name>/` (дата — текущая). Если
   каталог уже существует — остановись.
6. Найди оставшиеся ссылки на старый путь изменения:
   `rg "changes/<NNN-name>" -g "!spec/changes/archive/**"`. Исправь их на
   новый путь в архиве, если задачи изменения не задают иной цели.
   Копии Cursor-планов (`plan.md`, `spec/plans/*.plan.md`) не правь.
7. Предложи запись для `MEMORY.md`, если появился долгоживущий факт;
   записывай только после согласия.

## Запреты

- Не делай commit и push без просьбы.
