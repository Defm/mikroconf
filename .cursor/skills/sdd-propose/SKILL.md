# /sdd-propose — черновик спецификации

Ожидаемый режим: **Plan mode**. Первой строкой ответа назови режим. Если
режим другой — не выполняй шаг (без `spec/changes/` и без `CreatePlan`),
но **явно сообщи**: текущий режим, что `/sdd-propose` работает только в
Plan mode, и как переключиться (селектор под полем ввода или `Shift+Tab`).
Не молчи и не продолжай цикл.

Сразу после строки режима вставь две строки памятки SDD
из `USER-RULES.md` **дословно** и одной фразой отметь шаг `/sdd-propose`.

## Порядок

1. Определи имя изменения:
   - если передано аргументом — используй его;
   - иначе возьми номер на единицу больше максимального среди
     `spec/changes/NNN-*` и `spec/changes/archive/ГГГГ-ММ-ДД-NNN-*` (номер
     в архиве идёт после префикса даты) и краткое имя из диалога.
2. Создай `spec/changes/<NNN-name>/` по шаблонам `spec/templates/`:
   - `proposal.md` со строкой `Статус: draft`;
   - `tasks.md` — группы и задачи, у каждой строка `Проверка:`; задачи с
     RouterOS-устройствами, push, release или deploy помечай
     `Требует подтверждения:`;
   - `specs/<capability>/spec.md` — дельта по `delta-spec.md`;
   - `design.md` — только если есть неочевидные решения.
3. Заполняй по итогам диалога; неясное выноси в «Открытые вопросы», не
   додумывай.
4. Всегда вызови `CreatePlan` с тем же содержанием, что и черновик
   (зачем, что меняется, критерии, todos из `tasks.md`). Карточка плана
   должна появиться в UI.
5. Сразу сохрани полную копию плана (frontmatter и todos) в
   `spec/changes/<NNN-name>/plan.md`.
6. Покажи ссылки на созданные файлы и краткое содержание критериев приёмки.
   Предложи уточнить или написать «утверждаю».

## Правила

- Меняй только файлы в `spec/`.
- Статус `approved` ставь только по прямой просьбе пользователя
  («утверждаю», «approve»).
