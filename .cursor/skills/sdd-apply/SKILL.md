# /sdd-apply — реализация

Ожидаемый режим: **Agent mode**. Первой строкой ответа назови режим. В Plan
mode код не меняй и попроси переключиться.

Аргументы: `<NNN-name> [задача или группа]`, например `001-sdd-process 1.2`.
Если имя не передано, выбери через `AskQuestion` среди изменений со статусом
`approved` или `in-progress`; не угадывай.

## Проверки перед стартом

1. Прочитай `proposal.md`, `tasks.md`, `design.md` и `plan.md`, если они есть.
2. Если статус не `approved` и не `in-progress` — откажись и покажи раздел
   «Открытые вопросы».
3. Поставь `Статус: in-progress`, если стоял `approved`.

## Цикл

1. Возьми первую невыполненную задачу или указанную пользователем.
2. Выполни её, соблюдая «Вне рамок» и правила проекта.
3. Запусти проверку из строки `Проверка:`.
4. Если проверка прошла — отметь `- [x]` в `tasks.md` и обнови todo в
   `TodoWrite`. Копию `plan.md` не правь отдельно: синхронизируй её с
   оригиналом из `~/.cursor/plans` по правилу `AGENTS.md`.
5. Остановись с кратким отчётом: что сделано, результат проверки, следующая
   задача. Продолжай по «дальше».

Если пользователь явно попросил выполнить всё до конца — выполняй задачи
подряд по этому же циклу без отчёта после каждой. Всё равно остановись на
первой непройденной проверке, новом требовании или задаче
`Требует подтверждения:`.

## Старт после кнопки Build

Build запускает реализацию Cursor-плана. Задачи всё равно бери из `tasks.md`
изменения; todo плана — укрупнённое зеркало групп.

## Запреты

- Не расширяй код сверх spec. Новое требование — остановка и предложение
  правки `proposal.md`, `tasks.md` или дельты; код — после согласия.
- Задачи `Требует подтверждения:` — только после отдельного явного «да».
- Не делай commit и push без просьбы.
