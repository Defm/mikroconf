# Проектирование путей записи

## Принцип

Любой путь, способный менять RouterOS или внешнюю систему, закрыт по умолчанию. Read-only inventory и локальная подготовка не должны автоматически повышаться до write-доступа.

## Слои защиты

1. `.cursor/rules` задаёт обязательные ограничения для агента.
2. `beforeMCPExecution` блокирует MCP tools, имя которых указывает на запись.
3. `beforeShellExecution` требует отдельного подтверждения для SSH/SFTP/SCP и
   эквивалентных удалённых shell-путей.
4. `tools/check-repository.sh` проверяет состав Git и опасные артефакты.
5. Человек отдельно подтверждает конкретную удалённую операцию.

Hooks работают fail-closed: ошибка parser, неизвестный input или timeout
блокируют действие. Удалённая команда возвращает `ask`, а write-capable MCP
tool — `deny`. Hooks не заменяют least privilege, RouterOS safe mode, backup и
review.

## Разрешённый локальный путь

Обычное чтение, изменение файлов в репозитории, форматирование и локальные проверки не блокируются. Команды Git, изменяющие только локальный working tree/index, регулируются процессом; commit и push выполняются только по явной просьбе.

## Добавление нового write-path

Нужно описать цель, точный scope, authentication, idempotency, preconditions, dry-run, audit trail, timeout, rollback и способ аварийной остановки. До review новый путь остаётся выключенным.
